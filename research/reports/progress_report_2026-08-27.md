## 1. 背景：這個競賽在解什麼問題

### 1.1 現實問題

上市公司每年出版「永續報告書」（ESG 報告書），說明自己在環境（Environmental）、
社會（Social）、公司治理（Governance）三方面的作為。這類報告書篇幅動輒數百頁，
其中充滿各種**承諾**——例如「我們將於 2030 年達成碳中和」。

問題在於這些承諾**很難查證**。有些附有具體佐證（實際減碳數字、第三方查證報告），
有些則只有空泛宣示。後者正是「**漂綠**」（greenwashing）。人工逐段審閱數百家公司
的報告書不可行，因此需要自動化方法。

### 1.2 競賽把問題形式化成四個子任務

主辦單位（台北大學 Min-Yuh Day 教授團隊，與日本筑波大學 Yohei Seki 教授合作）
將問題拆解為四個分類任務。給定報告書中的**一個段落**，系統需同時判斷：

| 編號 | 子任務 | 中文說明 | 可能的答案 |
|---|---|---|---|
| ① | `promise_status` | 這段話有沒有包含一個 ESG 承諾？ | Yes / No |
| ② | `evidence_status` | 這個承諾有沒有具體證據支持？ | Yes / No / N/A |
| ③ | `evidence_quality` | 這個證據的品質如何？ | Clear / Not Clear / Misleading / N/A |
| ④ | `verification_timeline` | 這個承諾何時可以被驗證？ | already（已可驗證）/ within_2_years / between_2_and_5_years / more_than_5_years / N/A |

`N/A` 表示「不適用」。若①判定沒有承諾，則②③④都必然是 `N/A`。

**子任務③的三個等級定義**（引自官方標註準則）：

- **Clear**：資訊充分且具體，足以支持該承諾，內容可理解且合乎邏輯
- **Not Clear**：資訊缺漏，以致所述內容只能部分理解，或流於表面
- **Misleading**：該證據**無論真假**，與所主張的承諾之間沒有清楚關聯，看起來像是
  在轉移注意力

`Misleading` 就是漂綠偵測的核心。

### 1.3 官方評分方式

```
總分 = 0.20 × F1(①) + 0.30 × F1(②) + 0.35 × F1(③) + 0.15 × F1(④)
```

其中 F1 為 **macro-F1**：先分別計算每個類別的 F1，再取**未加權平均**——每個類別
同等權重，不管該類別有幾筆資料。

> **本版重要更新**：第 5 節說明為何本研究**不再以此公式作為評估標準**，以及改用
> 什麼。同時第 8 節記錄，我們原先對這個權重的批判其實過度了。

### 1.4 我們的參賽成績

我們（隊伍代號 TEAM_10671）的系統採用**三種預訓練語言模型 × 五折交叉驗證的集成**，
在官方測試集（2,000 段）取得**私榜第一名**：

| 系統 | 總分 | ① | ② | ③ | ④ |
|---|---:|---:|---:|---:|---:|
| 官方基線（大型語言模型，無檢索） | 0.4956 | 0.7298 | 0.5969 | 0.3549 | 0.3090 |
| 官方基線（大型語言模型 + 檢索） | 0.5111 | 0.7152 | 0.5958 | 0.3599 | 0.4227 |
| **我們的系統** | **0.6384** | 0.8191 | 0.7132 | 0.4642 | 0.6545 |

## 2. 研究目標

競賽結束後，主辦單位開放參賽隊伍投稿至 NTCIR-19 的專屬場次，審查標準明訂：著重
學術性、**不能只是競賽系統報告**、必須明確使用並分析競賽資料集。

觀察上表，四個子任務難度差異極大——③最難（0.4642）卻權重最高（0.35）。官方基線
在③也只有 0.3599。核心研究問題因此是：

> **子任務③（證據品質判斷）為什麼這麼難？困難的來源是什麼？能不能改善？**

**本版新增的第二個問題**（源於第 7 節的結果）：

> 既然③在九種介入下都無法改善，那麼**其他子任務**還有多少空間？以及，我們能否
> 說明清楚**③為什麼不能被改善**，讓它成為一項發現而非一句辯解？

## 3. 資料集

- **VeriPromiseESG4K**：4,000 個段落，來自 49 家台灣上市公司的 2024 年永續報告書
  （名義上 50 家；股票代號 3231 以 `Wistron` 與 `wistron` 兩種大小寫出現）
- **切分**：訓練 1,000 / 驗證 1,000 / 測試 2,000
- **候選段落**由 GPT-5 Pro 預先篩選，**標籤全部由人工標註**
- **標註流程**：21 位標註者分 7 組，多人獨立標註、逐輪計算一致性、每週檢討分歧

### 3.1 標註一致性（Krippendorff's Alpha）

| 子任務 | Alpha |
|---|---:|
| ① promise_status | 0.977 |
| ② evidence_status | 0.962 |
| ③ evidence_quality | **0.940** |
| ④ verification_timeline | 0.955 |

（Krippendorff's Alpha 衡量多位標註者的一致程度，1.0 為完全一致，一般 0.8 以上
視為高度一致。）

**這個數字排除了「標籤太主觀」這個解釋**——受訓的人類在③上高度一致，模型卻只有
0.4642。困難不在標籤。

### 3.2 跨度標註（`promise_string` / `evidence_string`）的實際結構

資料集除了四個分類標籤，還提供兩個**文字跨度**欄位，標出段落中「承諾是哪一句」與
「證據是哪一句」。三個檔案的欄位完全一致，都有這兩欄：

| 切分 | 總列數 | `promise_string` 非空 | `evidence_string` 非空 |
|---|---:|---:|---:|
| 訓練 | 1,000 | 814 | 677 |
| 驗證 | 1,000 | 813 | 668 |
| 測試 | 2,000 | 1,625 | 1,335 |

**覆蓋率是 100%**：凡 `promise_status=Yes` 的列，`promise_string` 必定有值；凡
`evidence_status=Yes` 的列，`evidence_string` 必定有值。

**這兩欄不是單一連續片段。** 約 21–28% 的值包含全形分隔符 `｜`，用來串接段落中
**數個不相鄰**的片段。例如：

```
promise_string: 於2021年11月正式承諾2050年達成淨零碳排放的承諾，初步規劃短、中、
                長期減碳策略。2 ｜ 未來將持續追蹤減碳成果，確保達成目標。
```

直接把整個欄位當成一個字串時，只有 72% 是段落的逐字子字串；**依 `｜` 切開後，
92–98% 的片段都是逐字子字串**。片段數的分布是：1 段 590 筆、2 段 164 筆、3 段 35 筆，
最多的一筆有 26 段。

| 切分 | 欄位 | 含分隔符 | 切開後全為逐字子字串 |
|---|---|---:|---:|
| 訓練 | `promise_string` | 28% | **98%** |
| 訓練 | `evidence_string` | 26% | **96%** |
| 測試 | `promise_string` | 21% | **92%** |
| 測試 | `evidence_string` | 17% | **89%** |

`promise_string` 的中位數長度是 50 字，段落中位數是 191 字，**約佔段落的四分之一**。

> **這是一個本版才發現的資料結構，而它影響了先前的一項結論。** 假設 B（把跨度當作
> 輸入過濾）在實作時把整個 `promise_string` 當成單一字串餵給模型，**其中含有 `｜`
> 分隔符與片段尾端殘留的段號數字**。也就是說那個實驗餵進去的並不是乾淨的承諾句，
> 而是帶雜訊的拼接字串。假設 B 的負面結果因此**需要重做才能確立**——見第 10.3 節。

### 3.3 子任務③的標籤分布（測試集 2,000 段）

| 類別 | 筆數 | 佔比 |
|---|---:|---:|
| Clear | 1,106 | 55.3% |
| N/A | 665 | 33.3% |

`Misleading` 在整個 4,000 段資料集中**只有 5 筆**（訓練 1、驗證 1、測試 3）。

## 4. 診斷：瓶頸的精確位置

### 4.1 逐類別拆解（我們的系統，子任務③）

| 類別 | 正確答案筆數 | 精確率 | 召回率 | F1 |
|---|---:|---:|---:|---:|
| Clear | 1,106 | 0.7857 | 0.8354 | 0.8098 |
| N/A | 665 | 0.7818 | 0.6195 | 0.6913 |
| Not Clear | 226 | 0.3131 | 0.4115 | **0.3556** |
| **Misleading** | **3** | 0.0000 | 0.0000 | **0.0000** |

系統在 2,000 筆中**一次都沒有輸出 `Misleading`**。

### 4.2 空間在哪裡（oracle 拆解）

每一列把系統的**一個元件**換成正確答案、其餘不動，藉此上界估計「把該元件做到完美」
能換到多少：

| 系統 | 子任務③ macro-F1 | 相對現況的增益 |
|---|---:|---:|
| 現況 | 0.4642 | — |
| ＋完美的閘門（②由正確答案提供） | 0.5796 | **+0.1155** |
| ＋完美的 Misleading（3 筆直接給對） | 0.7145 | **+0.2503** |
| ＋完美的判斷（Clear/Not Clear/Misleading 全對） | 0.8597 | +0.3955 |
| 完美 | 1.0000 | +0.5358 |

把「完美判斷」那列跟「完美 Misleading」那列相減可以分離兩者：完美判斷可得的
+0.3955 之中，**+0.2503 來自那 3 筆 Misleading**，剩下 +0.1452 才是全部 1,332 筆
Clear / Not Clear 判斷的總和。

**最大的單一槓桿，是那個沒有任何方法能偵測的類別。**

### 4.3 閘門（子任務②）的失效方向

`evidence_status` 混淆矩陣（列為正確答案，欄為預測）：

| 正解 \ 預測 | N/A | No | Yes | 合計 |
|---|---:|---:|---:|---:|
| **N/A** | 245 | 22 | 108 | 375 |
| **No** | 17 | 149 | **124** | 290 |
| **Yes** | 63 | 63 | 1209 | 1335 |

閘門只往一個方向失效：**232 筆在沒有證據的情況下被判為 `Yes`**（108 筆根本沒有
承諾、124 筆有承諾但無證據）。`No` 的召回率只有 **0.514**。這 232 筆接下來都會拿到
一個不可能正確的 Clear / Not Clear 標籤。

### 4.4 稀有不是病因

| 子任務 | 最稀有類別 | 測試 n | 訓練 n | 該類別 F1 |
|---|---|---:|---:|---:|
| ① | `No` | 375 | 373 | 0.7024 |
| ② | `No` | 290 | 282 | 0.5687 |
| ③ | **`Misleading`** | **3** | **2** | **0.0000** |
| ④ | `within_2_years` | 44 | 34 | 0.6465 |

`within_2_years` 只有 **34 筆**訓練資料，模型仍達到 F1 0.6465。`Misleading` 有
**2 筆**，F1 為 0。**可學習的門檻落在 2 到 34 之間，而只有 `Misleading` 掉在下面。**

## 5. 獨立的評估框架（本版新增）

### 5.1 為什麼需要

官方公式的 `0.20/0.30/0.35/0.15` 是**競賽設計選擇**，不是測量工具。我們檢視了
NTCIR-18 AI CUP 特別場次的三篇論文，作法一致：

| 論文 | 使用的評估指標 |
|---|---|
| KAP: MLLM-assisted OCR Text Enhancement | MRR、AP@1，另有獨立的「4.3 Evaluation Methodology」與消融設計 |
| Ensemble-Based Multi-Specialty Retrieval | Accuracy、F1、Precision，含非監督與監督兩種集成對照 |
| Translation or Multilingual Retrieval? | MRR@10、NDCG@10、Recall@100，含明確基線與近似上界、配對 t 檢定、錯誤分析、執行時間分析 |

**三篇都把競賽資料集當作素材，然後為自己的研究問題定義領域標準指標。沒有一篇把
排行榜分數當成論文的證據。**

### 5.2 本研究採用的框架

針對「階層式多任務分類」問題，我們建立對應的評估組合：

1. **四個子任務分開報告**，預設不合併成單一加權數字
2. **在極度不平衡下仍合理的指標**：balanced accuracy、Matthews 相關係數（MCC）、
   Cohen's kappa，與 macro-F1 並列
3. **整筆完全正確率（joint exact match）**：四個欄位**全部**答對的段落比例。這是
   稽核人員真正需要的量，而且它天然懲罰結構不一致，不需要自創指標
4. **條件式（階層式）評估**：每個子任務只在「正確答案使其適用」的列上評分，把
   閘門錯誤與判斷錯誤分開
5. **人類天花板正規化**：預測與正解之間的 Krippendorff's Alpha，除以主辦方報告的
   標註者間 Alpha。1.0 代表模型與正解的一致程度等同於標註者彼此的一致程度
6. **Bootstrap 信賴區間**
7. **加權敏感度分析**：換一種彙總方式，系統排名會不會變

### 5.3 結果一：排名不穩定，而我們當初選錯了提交

| 系統 | 競賽加權 | 均勻 macro-F1 | 均勻 MCC | 支持度加權 F1 | **整筆完全正確** | 人類天花板比 |
|---|---:|---:|---:|---:|---:|---:|
| `ens_3way_tuned` | **0.6384** | 0.6628 | 0.5628 | 0.7627 | **0.4880** | 0.583 |
| `ens_3way_raw` | 0.6362 | 0.6600 | **0.5680** | **0.7674** | **0.5130** | **0.585** |
| `ens_rob_mac_tuned` | 0.6342 | 0.6575 | 0.5580 | 0.7626 | 0.5065 | 0.577 |
| `roberta_large_cv5_ensemble` | 0.6267 | 0.6517 | 0.5497 | 0.7583 | 0.5005 | 0.567 |
| `roberta_large_cv5_ensemble_tuned` | 0.6136 | 0.6402 | 0.5479 | 0.7500 | 0.4910 | 0.567 |
| *參考：全猜多數類別* | 0.2484 | 0.2505 | 0.0000 | 0.4652 | 0.2920 | −0.190 |

**我們送出的 `ens_3way_tuned` 在競賽公式下第一，在整筆完全正確下最後**
（0.4880 對比 `ens_3way_raw` 的 0.5130）。兩者唯一的差別是逐類別門檻調校——它買到
競賽總分 +0.0022，卻付出整筆正確率 **−0.0250**。**實際使用這套系統的稽核人員會
偏好未調校的版本。**

### 5.4 結果二：換算到人類天花板，③沒有特別糟

| 子任務 | 與正解的 Alpha | 標註者的 Alpha | **比值** | 類別數 |
|---|---:|---:|---:|---:|
| ① promise_status | 0.6384 | 0.977 | **0.653** | 2 |
| ② evidence_status | 0.5783 | 0.962 | **0.601** | 3 |
| ③ evidence_quality | 0.4980 | 0.940 | **0.530** | 4 |
| ④ verification_timeline | 0.5226 | 0.955 | **0.547** | 5 |

在競賽 macro-F1 下，③（0.4642）看起來比④（0.6545）差了 0.19。**換算成「相對於
人類一致程度」，兩者幾乎一樣：0.530 對 0.547。**

換句話說，③看起來特別糟，**主要是 macro 平均把一個只有 3 筆的類別當成與其他類別
同等重要所造成的**。這是彙總方式的性質，與任何評分權重無關——第 5.5 節用完全不涉及
權重的方式重述同一件事。

同時：**沒有任何子任務達到人類天花板的三分之二**——四處都有空間。

### 5.5 結果三：三筆資料的槓桿，不需要提到競賽權重也成立

| 彙總方式 | 含 Misleading | 排除 Misleading | 差異 |
|---|---:|---:|---:|
| macro-F1 | 0.4642 | 0.6189 | **+0.1547** |
| 支持度加權 F1 | 0.7179 | 0.7189 | **+0.0011** |
| balanced accuracy | 0.4666 | 0.6222 | +0.1555 |

把 `Misleading` 從平均中拿掉，macro-F1 動 **+0.1547**，支持度加權 F1 動
**+0.0011**——**相差約 140 倍**。

這就是完整的論證：**當一個類別在 2,000 筆中只有 3 筆時，macro 平均不是可辯護的
彙總方式**。

> **本報告從此處起不再引用競賽的加權公式作為論據。** 本研究是以 VeriPromiseESG4K
> 為素材的獨立學術研究，競賽分數只在第 1.4 節作為系統來歷的背景交代，以及在方法
> 比較時作為一個可對照的既有數字。所有關於「這個類別有多大影響」的主張，都改用
> 上表這種與權重無關的方式陳述：**移除一個 3 筆的類別會讓 macro-F1 動 0.1547，
> 讓支持度加權 F1 動 0.0011，相差約 140 倍。**

### 5.6 結果四：條件式評估揭露標題數字有多少是閘門

| 子任務 | 適用列數 | 條件式 macro-F1 | 全部列 macro-F1 | 輸出了不可能標籤的列數 |
|---|---:|---:|---:|---:|
| ① | 2000 | 0.8191 | 0.8191 | 0 |
| ② | 1625 | **0.7500** | 0.7132 | 80 |
| ③ | 1335 | **0.4339** | 0.4642 | 115 |
| ④ | 1625 | **0.6710** | 0.6545 | 59 |

②和④在條件式下**上升**——它們的無條件分數有一大部分只是正確傳遞「這段沒有承諾」。
③則**下降**（0.4642 → 0.4339）：對它而言 `N/A` 那些列反而是簡單的部分，**判斷本身
比標題數字顯示的更難**。

最後一欄也取代了我們先前自創的「結構一致率」，換成可直接解讀的量：系統在 80 / 115
/ 59 列上輸出了準則所不允許的標籤。

## 6. 假設與實驗

### 假設 A：困難來自標註雜訊 → **排除**

Krippendorff's Alpha = 0.940（高度一致），模型 0.4642。人類做得到、模型做不到。

### 假設 B：應該「先定位、再判斷」（使用跨度標註）→ **不成立**

資料集為每個正例標出了「承諾是哪一句」與「證據是哪一句」，覆蓋率 100%，但所有
現有系統都沒有使用。

| 條件 | 輸入 | macro-F1 | 與 A 的差距 | 95% 信賴區間 |
|---|---|---:|---:|---|
| A | 完整段落（現行） | 0.3825 | — | — |
| B | 只給正確答案的證據跨度 | 0.3905 | +0.0080 | [−0.016, +0.032] |
| C | 承諾＋證據跨度 | 0.3915 | +0.0089 | [−0.009, +0.027] |
| D | **對照**：等長隨機片段 | 0.3755 | −0.0071 | [−0.033, +0.019] |

改善僅 +0.008 且信賴區間跨零。補充：證據跨度的中位數長度是整段的 **52.2%**，
「只看證據那句」其實只濾掉一半文字。

*方法限制*：此實驗用字元 n-gram 傳統統計模型，該模型在 `Not Clear` 上只有 0.2394，
明顯弱於神經網路（0.4296），因此不能完全排除。

#### 假設 B 以清理後的跨度重做

先前的實作把跨度欄位當成單一字串使用（見第 3.2 節）。以同一模型、同一切分、同一隨機
種子，僅改為依分隔符 `｜` 切開並去除尾端殘留數字後重跑：

| 條件 | macro-F1 | 與 A 的差距 | bootstrap 95% 信賴區間 |
|---|---:|---:|---|
| A　完整段落 | 0.3825 | — | — |
| B　清理後的證據跨度 | 0.3930 | +0.0105 | [−0.0134, +0.0358] |
| C　清理後的承諾＋證據 | 0.3860 | +0.0035 | [−0.0117, +0.0190] |
| D　隨機對照 | 0.3655 | −0.0170 | [−0.0405, +0.0081] |
| E　**未清理**（先前實際使用的輸入） | 0.3905 | +0.0080 | [−0.0159, +0.0319] |

**不足以解釋原本的負面結果**——假設 B 失敗的原因不是輸入髒。信賴區間仍跨越零，
結論維持不變。

（清理的效果：含分隔符的比例 22%；逐字子字串的比例從 73% 提升到 **96%**。）

### 假設 C：跨度的價值在「關係」而非過濾 → **推翻**

準則對 `Misleading` 的定義是關係性的（「與承諾沒有清楚關聯」），因此可用語意關聯度
做**零樣本**偵測，繞過只有 2 筆訓練資料的困境。

| 分數 | Clear | Not Clear | Misleading | AUC |
|---|---:|---:|---:|---:|
| bge-m3 餘弦相似度 | 0.6441 | 0.6583 | 0.6341 | **0.4671** |
| 交叉編碼器分數 | −1.3269 | −1.1670 | −1.1693 | **0.5095** |
| 證據長度 ÷ 承諾長度 | 3.72 | 2.11 | 1.62 | **0.6542** |

（AUC 衡量排序能力，0.5 = 等同亂猜。）

兩個語意模型都在亂猜水準，雙塔編碼器甚至**低於 0.5**——代表 `Not Clear` 的證據跟
承諾**更相似**，方向與假設相反。五筆 `Misleading` 的關聯度百分位是
54.9 / 10.8 / 72.8 / 8.5 / **90.7**，其中一筆是全資料集中最相關的那一端。

**存活的發現**：`證據長度 ÷ 承諾長度` AUC 0.6542，且詞彙版（0.6535）與語意版
（0.6542）幾乎相同，代表它是**長度效應**而非語意效應。

**衍生結論**：運作中的構念是「**鋪陳程度**」而非「關聯度」——Clear 的證據比承諾長
得多且帶進新內容；Not Clear 的證據短，且只是換句話說重複承諾。

### 假設 D：模型沒學到準則明列的判準 → **關聯強，但不是瓶頸**

依準則原文列舉的項目（時程、數字、百分比、負責單位、第三方查證）寫成 12 條正規
表示式加 2 個長度特徵：

| 特徵 | 有此特徵時 P(Clear) | 無此特徵時 | Cramér's V |
|---|---:|---:|---:|
| `has_digit` | 0.934 | 0.666 | **0.348** |
| `has_year` | 0.938 | 0.755 | 0.243 |
| `has_percent` | 0.978 | 0.809 | 0.156 |

（基準 P(Clear) = 0.832。Cramér's V 衡量關聯強度，0 = 無關聯。）

在「Clear vs Not Clear」二元分類上：14 條手寫規則得 0.6518，我們的三模型集成得
0.6602，**差距僅 0.0084**。

*但這個比較後來被修正*——見假設 E。

### 假設 E：把子任務③獨立出來訓練 → **隔離條件下成立，端到端不成立**

現行架構是**多任務學習**（一個共用語言模型上接四個分類頭）。改為專用模型：

| 系統 | 交叉驗證 | 測試集 |
|---|---:|---:|
| 專用二元模型（單一模型） | 0.7093 | **0.7104** |
| 14 條正規表示式 | 0.6388 | 0.6512 |
| 三模型五折集成 | — | 0.6602 |

單一專用模型超越整套集成 +0.05。**但這是在「正確答案告訴我們這段有證據」的前提下
量的。** 實際系統必須自己先判斷②。

端到端驗證：總分 0.6384 → **0.6368**，增益消失。`N/A` 上升（0.6913 → 0.7075），
`Not Clear` 下降（0.3556 → 0.3223）。

**原先的量測是在解一個較簡單的問題。**

### 假設 F：強制邏輯一致會改善結果 → **在多任務架構上成立，但不可推廣**（本版修正）

直覺上，把預測投影到合法的標籤組合上應該只會更好，因為正確答案 100% 合法。

**在多任務架構上，這是錯的**——同一組權重下，投影使總分從 0.6015 掉到 0.5885
（**−0.0130**），幾乎全落在子任務③（0.4472 → 0.4091）。

機制：把測試集依「②是否預測正確」切開，②正確的 1,603 筆上強制一致有幫助
（0.848 → 0.867），②錯誤的 397 筆上有害（0.176 → 0.121）。原始準確率幾乎抵銷，
但 macro-F1 不是準確率——強制一致把質量推向 `N/A`（第二大類），代價是 `Not Clear`
的召回，而 macro 平均給小類別同等權重。

**本版的修正**：這個效應在**專用模型架構上不複現**。同樣的投影操作代價是
**+0.0013**（1 骨幹）與 **+0.0003**（3 骨幹）——零，方向還相反。

前版宣稱有「三次獨立量測」，但三次**都跑在多任務或串接架構上**，沒有一次是真正的
獨立複現。正確的說法是：**這是多任務架構的性質，不是這個任務或這個指標的性質。**

一個合理的機制：多任務模型共用編碼器，四個頭高度相關，違反邏輯通常代表整列的表徵
都錯了，投影只是傳播錯誤；四個獨立訓練的模型各自獨立失準，違反邏輯較常是「一個頭
錯、三個對」，那正是投影修得好的情況。

### 假設 G：`Misleading` 可用「定義」而非「範例」偵測 → **完全失敗**

用 Qwen3-8B（80 億參數指令微調模型），提示詞寫入準則原文的三個定義，不給任何範例：

| 類別 | 正解筆數 | 模型預測筆數 | 精確率 | 召回率 | F1 |
|---|---:|---:|---:|---:|---:|
| Clear | 2,224 | 1,482 | 0.895 | 0.596 | 0.716 |
| Not Clear | 451 | 1,191 | 0.247 | 0.652 | 0.358 |
| **Misleading** | **5** | **7** | **0.000** | **0.000** | **0.000** |

五筆**一筆都沒抓到**（四筆判成 `Not Clear`、一筆 `Clear`）。模型確實輸出了
`Misleading` 七次，所以不是拒絕使用該標籤，而是從未與標註者一致。

### 假設 I：LLM 資料擴增能救稀有類別 → **有害**（本版新增）

把標籤翻過去。每個目標類別生成 300 筆。所有評估都在真實測試集上。

`evidence_quality`：

| ＋合成 Not Clear | 2300 | 0.3994 | 0.6720 | 0.2993 | 0.0000 |
| ＋合成 Misleading | 2300 | 0.4039 | 0.6379 | 0.3610 | 0.0000 |

### 假設 K：4 epochs 訓練不足，掩蓋了架構比較 → **否**（本版新增）

跑 15 epochs 並逐 epoch 評估驗證折，讓 4-epoch、15-epoch 與中間曲線都出自同一次訓練：

| 子任務 | ep1 | ep2 | **ep3** | ep4 | ep8 | ep15 | 從 ep4 到最佳 |
|---|---:|---:|---:|---:|---:|---:|---:|
| ① promise_status | 0.562 | 0.769 | 0.782 | 0.788 | 0.784 | 0.786 | +0.0088 |
| ② evidence_status | 0.467 | 0.602 | 0.657 | 0.662 | 0.682 | 0.688 | **+0.0277** |
| ③ **evidence_quality** | 0.251 | 0.448 | **0.501** | **0.501** | 0.503 | 0.505 | **+0.0049** |
| ④ verification_timeline | 0.249 | 0.448 | 0.555 | 0.588 | 0.615 | 0.625 | **+0.0383** |

**③在第 3 個 epoch 到達 0.501，跑到第 15 個 epoch 是 0.505——多訓練 12 個 epoch
只換到 0.0049。** 同一段區間內④漲了 0.0383、②漲了 0.0277。

**四個子任務有三個在 epoch 4 時還受限於最佳化；③從 epoch 3 之後完全不受最佳化限制。**

訓練預算對總分的影響：4 → 15 epochs 只值 **+0.0039**。逐子任務挑最佳 epoch
（0.6143）並沒有比直接跑滿 15 epochs（0.6154）好——epoch 8 之後曲線太平，挑選等於
擬合驗證雜訊。

*一個必須標注的瑕疵*：上表的「4 epochs」是 15-epoch OneCycle 排程走到第 4 個 epoch
的檢查點，學習率仍接近峰值，與假設 H 中完整退火的 4-epoch 執行**不是同一個模型，
不能相減**。本表**內部**的逐 epoch 比較共用同一排程，有效。

### 假設 L：把大型語言模型加入集成投票 → **無效**（本版新增）

**動機**：集成是本研究唯一穩定的增益來源（三骨幹比單骨幹 +0.0142）。但那三個骨幹
都是 3 億參數級、同一資料、同一目標訓練出來的 BERT 家族模型，**錯誤模式高度相關**。
一個 80–320 億參數的生成式模型錯得不一樣，而「錯得不一樣」正是投票需要的性質。

**評分方式**：把每個子任務寫成帶字母選項的單選題，提示詞結尾停在「答案：」，
**只讀那一個位置的 logits**、限制在選項字母上做 softmax。每個（段落, 子任務）只要
一次前向傳播，得到的是校準過的機率分布，可直接進加權投票。

**候選模型**（全部以 bitsandbytes NF4 4-bit 統一量化，另加一個 bf16 對照）：
Qwen3-8B（bf16 與 NF4）、Qwen3-14B、Qwen3-32B、Gemma-3-12B-it、Gemma-3-27B-it、
DeepSeek-R1-Distill-Qwen-32B。

**評估協定**：在 train+val 的 601 筆分層子樣本上評分（測試集完全不碰）。混合方式為
`(1−w) × 編碼器折外機率 + w × 語言模型機率`。**權重在半數子樣本上擬合、在另一半上
評估，再交換取平均**——所有回報的增益都是對權重而言的樣本外估計。

**結果**：

| 子任務 | 編碼器單獨 | 最佳誠實增益 |
|---|---:|---:|
| ① promise_status | 0.7849 | +0.0040 |
| ② evidence_status | 0.6604 | 0.0000 |
| ③ **evidence_quality** | 0.4140 | **−0.0046**（七個模型全部為負） |
| ④ verification_timeline | 0.5338 | +0.0033 |

28 個「模型 × 子任務」組合中，誠實增益為正的只有 2 格，都在 +0.004 以內，遠小於
n=601 的雜訊帶。**③——本研究最想改善的子任務——七個模型全部使其變差**
（−0.0046 至 −0.0269）。

即使允許每個子任務各自挑選最適合的模型，加權總計也只動 **+0.0013**，而且「哪個模型
最好」本身也是在同一批 601 筆上挑的。

**這個實驗的方法論價值大於其結果。** 同一組資料、同一個模型（Qwen3-8B 在④上）：

| 讀法 | 增益 |
|---|---:|
| Oracle（在同一批資料上挑最佳權重） | **+0.0168** |
| 誠實（權重擬合與評估分開） | **−0.0194** |

原因在擬合出的權重本身：**A 半選 0.30、B 半選 0.05，相差六倍**。那不是在定位最佳
權重，是在擬合雜訊。這正好驗證第 5 節評估框架的主張：**樣本量小時，未經樣本外驗證
的數字沒有意義。**

**兩個附帶觀察值得保留**：

1. **量化幾乎免費**。Qwen3-8B 的 bf16 與 NF4 在四個子任務上差距 ≤0.016，NF4 在③上
   還略勝（0.2612 vs 0.2456）。以 4-bit 掃描模型家族是有依據的做法，不是將就。
2. **規模沒有幫助，而且最強的個體不是最好的集成成員**。8B → 14B → 32B 在①②④上
   都是下降的。Qwen3-32B 單獨分數最高，但在③上與編碼器的**互補性最低**
   （「僅語言模型答對」0.126，14B 是 0.170）——它變強的方式是變得更像編碼器，
   而那正是投票用不上的。

### 假設 M：檢索增強（RAG）→ **總體無效，但單一子任務成立**（本版新增）

**動機**：前八個失敗有一個共同性質——訓練更久、更多資料、調門檻、換架構、換模型、
加投票，**全都是在改「怎麼學」或「怎麼合併」，沒有一個改變模型能看到的資訊**。而
訓練曲線顯示③在第 3 個 epoch 就飽和，代表輸入裡的資訊已被榨乾。檢索是第一個真正
增加資訊的介入。

分兩階段執行，都不需要外部語料：

- **A 階段（檢索當機率訊號）**：用 `BAAI/bge-m3` 嵌入全部段落，對每個段落找出最相似
  的 k 個鄰居，以相似度加權投票它們的標籤，再與編碼器的機率混合。
- **B 階段（檢索當提示範例）**：把同一批鄰居**連同它們的正確標籤**放進提示詞，讓

### 假設 N：`Misleading` 只是超出我們的算力，不是本質不可偵測 → **推翻**（本版新增）

**動機**：到此為止，所有找不到 `Misleading` 的嘗試都用了**至多 320 億參數、量化過、
跑在單張消費級顯示卡上**的模型。所以「沒有方法找得到」實際上只是「**我們跑得動的**
方法找不到」——這是算力限制，不是任務性質。

要讓「這個類別無法被自動方法認出」成為發現而非抱怨，必須排除算力這個解釋。

**實驗設計**：用三家廠商當前的前沿模型，以準則原文的定義作提示（不給範例），對測試集
中 `evidence_status=Yes` 的全部 1,335 列判斷 `evidence_quality`。這個集合包含測試集
**全部 3 筆** `Misleading`。

| 模型 | macro-F1 | Clear | Not Clear | **Misleading** | 輸出 Misleading 次數 | 抓到 |
|---|---:|---:|---:|---:|---:|---:|
| claude-opus-5 | 0.3538 | 0.6721 | 0.3892 | **0.0000** | 7 | **0 / 3** |
| claude-sonnet-5 | 0.4489 | 0.8649 | 0.4819 | **0.0000** | 2 | **0 / 3** |
| gpt-5.6-sol | 0.4325 | 0.8389 | 0.4587 | **0.0000** | 5 | **0 / 3** |
| gemini-3.7-flash | 0.4143 | 0.8355 | 0.4073 | **0.0000** | 4 | **0 / 3** |

#### 四個模型對三筆的判斷完全一致

| id | claude-opus-5 | claude-sonnet-5 | gemini-3.7-flash | gpt-5.6-sol |
|---|---|---|---|---|
| 12010 | Not Clear | Not Clear | Not Clear | Not Clear |
| 12772 | **Clear** | **Clear** | **Clear** | **Clear** |
| 13102 | Not Clear | Not Clear | Not Clear | Not Clear |

**三家公司、四個獨立訓練的系統，逐筆給出同一個答案，而且都不是標註者的答案。**
這比「四次獨立失敗」強得多——這些模型讀這些段落的方式是**一致的**，只是跟標註者不同。

#### 它們不是拒絕使用這個標籤

四個模型在 1,335 列中總共輸出了 **18 次** `Misleading`（opus-5 七次、gpt-5.6 五次、
gemini 四次、sonnet 兩次），**每一次都是錯的**。模型理解這個類別、願意使用它，只是
**從來沒有跟標註者指向同一批段落**。

這排除了最直觀的解釋——「定義沒有傳達清楚」。

#### 兩個附帶觀察

**前沿零樣本輸給微調的小模型。** 最佳的 API 模型在這個三分類問題上是 0.4489，而我們的
三骨幹集成在對應的二元部分是 0.6602。**規模與新近度取代不了監督式訓練。**

**能力更強反而更差。** claude-opus-5 是四個裡最低的（0.3538），比 claude-sonnet-5 低
0.095，而且差距集中在 `Clear`（0.6721 vs 0.8649）；它輸出 `Misleading` 的次數也最多。
合理的解釋是**更強的推理讓模型更願意挑證據的毛病**，於是偏離了「大多不挑毛病」的
標註者。這與本地實驗的形狀一致——Qwen3-32B 單獨分數最高，卻與編碼器最相似、對投票
貢獻最小。

## 7. 主要發現

### 7.1 子任務③的困難在輸入層次，不在最佳化層次

**九個彼此獨立的介入都推不動它**：

| 介入方式 | 結果 | 出處 |
|---|---|---|
| 訓練更久 | 12 個 epoch 換 +0.0049 | 假設 K |
| 給稀有類別更多資料 | 每個條件都更差 | 假設 I |
| 降低預測門檻 | 單調下滑，無內部最佳解 | 假設 J |
| 跨度標註當輸入 | +0.008，信賴區間跨零 | 假設 B |
| 跨度標註當關係 | AUC 0.4671，低於亂猜 | 假設 C |
| 專用頭取代多任務頭 | 0.4246 vs 0.4472，無增益 | 假設 H |
| 手寫準則特徵融合 | 堆疊比單模型差 | 假設 D／E |
| **大型語言模型投票** | **七個模型全部為負** | 假設 L |
| **檢索增強** | **測試集 +0.0006** | 假設 M |

加上飽和曲線（第 3 個 epoch 之後不再進步），可以說：**它不是訓練不足、不是資料
不夠、不是參數不夠、也不是門檻沒調好。** 這讓「無法改善③」成為一項發現而非辯解。

### 7.2 `Misleading` 兩個方向都不可及

| 方向 | 方法 | 規模 | 結果 |
|---|---|---|---|
| **辨識** | 微調三骨幹集成 | 3×340M | 2,000 筆中預測 **0 次** |
| **辨識** | 語意關聯度（零樣本） | 568M | AUC **0.4671**（低於亂猜） |
| **辨識** | 定義式 LLM（零樣本） | 8B | **0/5** |
| **辨識** | 檢索範例提示 | 8B | 預測 **0 次** |
| **辨識** | **前沿 API 模型 ×4** | **前沿** | **0/3，且 18 次誤報** |
| **生成** | 引導式最小編輯 LLM | 8B | 300 筆合成 → 召回 **0** |

而標註者在該欄位的 Krippendorff's Alpha 是 **0.940**。

**加入前沿模型之後，這個主張的性質改變了。** 原本只能說「我們跑得動的方法找不到」，
受限於單張消費級顯示卡；現在可以說：

> **包含 Anthropic、OpenAI、Google 當前最強的商用模型在內，沒有任何方法能認出這個
> 類別哪怕一次，而受訓的人類標註者在同一個欄位達到 Krippendorff's Alpha 0.940。**

這是**資料集與評測設計的性質，不是任何特定系統的能力限制**。

其學術意義不在於「它值多少分」，而在於：**一個由人類可靠標註、且對應到實務上最重要
概念（漂綠）的類別，在只有 5 個樣本的情況下，對所有已知的自動方法都是不可及的。**
這對「稀有但關鍵的類別該如何納入評測」提出了一個具體問題——若一個類別無法被任何方法
學會，把它放進未加權平均，量到的就不是系統能力，而是該類別的樣本數。

### 7.3 macro 平均在這個資料集上不可辯護

拿掉 `Misleading` 使 macro-F1 動 +0.1547、支持度加權 F1 動 +0.0011，**相差 140 倍**。
這個論證不需要引用任何競賽權重。

### 7.4 ③與④的困難性質不同——這是本研究的核心對比

把所有介入按子任務整理，出現一個清楚的分裂：

| 介入 | ③ evidence_quality | ④ verification_timeline |
|---|---:|---:|
| 專用模型取代多任務頭 | 無增益 | **+0.0952 / +0.0557**（兩次獨立實驗） |
| 大型語言模型投票 | 七個模型全負 | +0.0033 |
| **檢索增強（測試集實測）** | **+0.0006** | **+0.0110** |
| 訓練更久 | +0.0049 | +0.0383 |

**三種彼此獨立的方法都改善④，九種方法都推不動③。**

機制上說得通：④判斷「何時可驗證」，大量取決於**措辭慣例**——「已完成」「將於 2030
年」「持續推動」。檢索抓得到這種表面規律（鄰居標籤一致性 1.45× 隨機，其餘子任務只有
1.11–1.18×），專用模型也抓得到，訓練更久也還在進步。

③判斷「證據是否充分」，需要的是**對證據內容的評估**，而那個資訊不在段落的表面形式
裡。訓練曲線在第 3 個 epoch 就飽和，正是「輸入裡沒有更多東西可抽」的直接證據。

**這個對比讓「我們改善不了③」從辯解變成主張**：不是方法不夠好，而是兩個子任務的
困難位於不同層次。

### 7.5 競賽權重不影響最優系統（本版修正前版說法）

把機率固定、只調逐類別先驗，針對四個目標各配一組規則再交叉評估：

| 為誰配的規則 \ 用誰評分 | 競賽加權 | 均勻 | 整筆正確 | MCC |
|---|---:|---:|---:|---:|
| 不調整 | 0.6018 | 0.6231 | 0.3605 | 0.5009 |
| 為競賽加權配 | **0.6176** | 0.6398 | 0.4365 | 0.5296 |
| 為均勻配 | 0.6176 | **0.6398** | 0.4365 | 0.5296 |
| 為整筆正確配 | 0.5790 | 0.6067 | **0.4535** | 0.5131 |
| 為 MCC 配 | 0.6154 | 0.6382 | 0.4400 | **0.5332** |

**競賽加權與均勻加權配出同一組規則，每欄分數完全一樣。** 改權重改變的只是你報出來
的數字，不是你會建的系統。

**真正的張力在 macro 平均 vs 整筆完全正確**：優化 macro 家族要付 0.0170 的整筆
正確；優化整筆正確要付 0.0386 的競賽分數。MCC 站在 macro 家族這邊。

論文的指標論證應該是 **macro-F1 對比整筆完全正確**，而不是權重。

### 7.6 專用模型只在子任務④有效

在 1 骨幹自由組合下，專用與多任務**完全相同**（0.6015 vs 0.6015）。唯一動的是
④：0.5291 → 0.5848（**+0.0557**）。方向與另一次獨立實驗（+0.0952）一致，**是目前
唯一跨兩次實驗複現的正向結果**。

而④正是官方基線最弱的子任務（0.4227）。

### 7.7 競賽集成的領先幾乎全部來自集成本身

0.6384 與 0.6157 的差距是 0.0230，其中訓練預算佔 **+0.0039**、集成（1→3 骨幹）佔
**+0.0142**，合計約 0.018。**留給「多任務 vs 專用」的空間所剩無幾**——與 7.5 節
量到兩種形式化都是 0.6015 一致。

## 9. 資料集品質與可重現性

### 9.1 資料集缺陷（建議回報主辦方）

1. **訓練集與驗證集用兩種編碼表示同一個「不適用」**：訓練集的 186 筆（①=No）在
   ②③④欄位是**空字串**，驗證集的 187 筆是 `"N/A"`，官方提交範例用 `"N/A"`。直接
   使用訓練集而未正規化的隊伍，模型會輸出空字串，在官方評分下該列直接零分。
2. **公司數被高估**：股票代號 3231 以 `Wistron` 與 `wistron` 兩種寫法出現。
3. **`esg_type` 多標籤排序不一致**：`E;S`（23 筆）與 `S;E`（12 筆）表示相同內容卻
   是不同字串，另有 21 筆空值。

### 9.2 一個值得寫入論文的可重現性陷阱

`IDEA-CCNL/Erlangshen-DeBERTa-v2-320M-Chinese` 的 **checkpoint 權重以 fp16 儲存**。
載入後編碼器輸出 Half、分類頭是 fp32。

- 若使用 `torch.amp.GradScaler`，會直接報錯 `Attempting to unscale FP16 gradients`
- 若移除 GradScaler（用 bf16 時它本來就是空操作），AdamW **不報錯、直接下溢**——
  模型完全沒學到東西

唯一的徵兆是分數剛好等於「永遠預測少數類別」：`promise_status` 的折外 macro-F1 為
**0.1572**，而全部預測 `No` 的理論值是 `(2×373/(373+2000) + 0)/2 = 0.157`。

修正方式是載入後對模型呼叫 `.float()`。修正後該骨幹的折外分數為
0.7956 / 0.6625 / 0.4197 / 0.5638。

**一個以 fp16 發布的 checkpoint 會靜默地訓練失敗而非報錯**，這值得在可重現性章節
提出。

### 9.3 量化後端的連鎖失效

`transformers` 5.16 已將 AWQ 格式改由 `gptqmodel` 後端載入，而該套件要求
torch ≥ 2.11（本專案所有編碼器實驗都在 2.8 上驗證過）。安裝它時會連帶拉進一個
`torchao`，而 `transformers` 的量化器派發模組會**無條件 import `torchao`**——於是
連原本可用的 bitsandbytes 路徑也一起失效。

錯誤訊息是 `cannot import name 'ScalingType' from 'torch.nn.functional'`，指向
torch 版本，**而非真正的肇因**。移除 `torchao` 後一切恢復正常。

教訓：**為了支援 A 而安裝的套件，可能靜默地讓 B 失效，而錯誤訊息不會指向它。**

### 9.4 大型檔案下載的兩個陷阱

在記憶體受限的機器（本例為 3.7GB cgroup 上限）下載 4.85GB 的模型分片時：

1. `huggingface_hub` 的下載程序會被 OOM 終止，**沒有 traceback、log 裡什麼都沒有**
2. 更關鍵的是它**跨程序不續傳**——每次重啟建立新的 `.incomplete` 暫存檔，同一個
   分片累積出多個半殘檔。實測 42GB 磁碟用量、**0 個完整檔案**

改用 `curl -C -` 即解決：固定記憶體串流、對同一檔案做位元組範圍續傳。實測吞吐
60 MB/s，是前者的兩倍以上。

### 9.5 磁碟配額錯誤會偽裝成其他問題

網路磁碟（MooseFS）的**每使用者配額**用 `df` 看不出來——`df` 顯示的是整個共享叢集
（2.1P、84%），而實際配額約 100GB。配額用盡時，檔案寫入會產生 0 位元組的檔案，
下游症狀五花八門：base64 解碼產出空檔、JSON 設定檔變成 0 bytes 導致
`JSONDecodeError`、模型載入失敗。

真正的錯誤訊息 `base64: write error: Disk quota exceeded` 只在原始輸出裡出現一次。
**應該在第一次異常時就去讀原始錯誤，而不是從症狀推測原因。**

## 11. 術語表

| 術語 | 說明 |
|---|---|
| **macro-F1** | 先算每個類別的 F1，再取未加權平均。小類別與大類別權重相同 |
| **支持度加權 F1** | 同上，但依各類別的樣本數加權 |
| **精確率 / 召回率** | 精確率：預測為某類的樣本中實際正確的比例。召回率：實際屬於某類的樣本中被找出的比例 |
| **balanced accuracy** | 各類別召回率的未加權平均 |
| **MCC（Matthews 相關係數）** | 在類別不平衡下仍穩健的單一數字指標，範圍 −1 到 1，0 為隨機 |
| **Cohen's kappa** | 扣除隨機一致後的一致程度 |
| **Krippendorff's Alpha** | 衡量標註者一致程度，可用於兩位以上的標註者；本研究也用它衡量「模型與正解」的一致程度，以便與標註者間的數值直接比較 |
| **AUC** | ROC 曲線下面積，衡量排序能力。0.5 = 等同亂猜 |
| **Cramér's V** | 兩個類別變數的關聯強度，0 = 無關聯 |
| **整筆完全正確（joint exact match）** | 四個欄位全部答對的段落比例 |
| **條件式評估** | 每個子任務只在「正確答案使其適用」的列上評分 |
| **人類天花板比** | 模型與正解的 Alpha ÷ 標註者間的 Alpha |
| **交叉驗證 / 折外預測（OOF）** | 把訓練資料切成 K 份輪流驗證；折外預測指每筆資料由「沒看過它的模型」所做的預測 |
| **集成 (Ensemble)** | 訓練多個模型並綜合其預測 |
| **骨幹 (Backbone)** | 系統所使用的預訓練語言模型本體 |
| **多任務學習** | 一個共用模型本體上接多個分類頭，同時學習多個任務 |
| **零樣本 (Zero-shot)** | 不提供任何訓練範例，僅靠任務描述讓模型作答 |
| **跨度標註 (Span)** | 標出文本中特定文字片段的起訖位置 |
| **雙塔 / 交叉編碼器** | 雙塔分別編碼兩段文字再算相似度（快）；交叉編碼器把兩段一起輸入直接輸出分數（準但慢） |
| **投影到合法集合** | 把違反標註階層邏輯的預測改成最接近的合法組合 |
| **LoRA** | 低秩適配，只訓練少量新增參數即可微調大型模型 |
| **RAG（檢索增強生成）** | 先檢索相關文件片段，再連同問題一起餵給模型 |
| **信賴區間 / Bootstrap** | 以重複抽樣估計統計量的不確定範圍；區間跨越 0 表示無法排除「沒有效果」 |
