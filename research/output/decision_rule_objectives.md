# What the choice of objective does to the decision rule

Generated by `research/scripts/18_decision_rule_objectives.py`. Encoder `hfl/chinese-roberta-wwm-ext-large`, 5-fold CV, probabilities held fixed; only a class-wise multiplicative prior varies, fitted by coordinate ascent.

Out-of-fold pool sizes: promise_status 2000, evidence_status 2000, evidence_quality 2000, verification_timeline 2000.

## Oracle: how far apart can the objectives pull?

Each rule is fitted directly on test against one objective, then scored under all four. Not a performance claim -- an upper bound on the disagreement between objectives.

|---|---:|---:|---:|---:|
| **no adjustment (argmax)** | 0.6018 | 0.6231 | 0.3605 | 0.5009 |
| fitted for `competition` | **0.6176** | 0.6398 | 0.4365 | 0.5296 |
| fitted for `uniform` | 0.6176 | **0.6398** | 0.4365 | 0.5296 |
| fitted for `exact` | 0.5790 | 0.6067 | **0.4535** | 0.5131 |
| fitted for `mcc` | 0.6154 | 0.6382 | 0.4400 | **0.5332** |

The two corners of the trade: optimising the competition objective reaches 0.6176 on it while giving up 0.0170 on exact match; optimising exact match reaches 0.4535 while giving up 0.0386 on the competition objective. The rules are not the same rule.

## Reading

**The competition weighting turns out not to matter.** `competition` and
`uniform` fit the *same rule* and score identically in every column, oracle and
honest alike. Re-weighting 0.20/0.30/0.35/0.15 against 0.25 each changes which
number you report, not which system you would build.

That corrects the framing in script 16. The claim that "Misleading decides 8.75
points" is arithmetically true and still says something about how the
leaderboard was decided, but it does not support the stronger reading -- that the
weighting distorted what anyone would build. It did not.

**The real tension is macro-averaging against joint accuracy.** Those two do
pull to genuinely different rules. Optimising the macro-F1 family costs 0.0170
of exact match; optimising exact match costs 0.0386 of the competition score.
Since the macro family (competition, uniform, and MCC, which lands close) all
agree with each other, the paper's metric argument should be about *macro-F1 vs
exact match*, which is a real methodological choice, not about the weights.

**Prior adjustment is worth about +0.007 honestly.** Out-of-fold fitting lifts
the competition score 0.6018 to 0.6088, against an oracle ceiling of 0.6176. So
roughly half the available gain survives honest tuning -- real, but small.

**The `evidence_status = No` headroom is not reachable this way.** Every step up
in the prior buys recall, 0.6414 to 0.8897, and every step loses macro-F1,
0.6734 to 0.5995, along with the competition score and exact match. The curve is
monotone in both directions with no interior optimum, which means precision
falls faster than recall rises across the whole range. The limit is where the
model *ranks* these rows, not where the threshold sits, so no decision rule
recovers the headroom script 17 identified.

That last point matters because it is the same result script 19 reaches from the
other direction. Threshold adjustment and synthetic data both buy recall on a
starved class and both lose more precision than they gain, which points at the
ranking rather than the decision rule or the training-set size as the binding
constraint.
