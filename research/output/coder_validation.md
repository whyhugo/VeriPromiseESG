# Does the automatic coder do what it claims?

Generated by `research/scripts/41_coder_validation.py`. 60 reasons drawn at random from those script 35 collected, across all four models, coded by hand against the same seven categories.

**The manual codes and the regular expressions have the same author.** This therefore bounds coder error against its author's intention; it is not an independent validation, and an outside annotator would be worth having before publication. The sample and the manual codes are stored with the script so that can be done without repeating the work.

## Reading

**The two categories the argument rests on hold; the rest do not.** `stated: vague wording` and `unstated: no concrete figures` are the only two used to make a claim, and they reach kappa 0.963 and 0.861 with one and three misses respectively. Every measurement in script 35 that this project relies on -- the 0.714 citation rate on disputed rows, the 84% co-occurrence -- is built from those two.

The auxiliary categories are weak and should be read as indicative only. `insufficient detail` misses 11 of 16, because reasons phrase it as missing 專案內容 or 投入資源 rather than the nouns the pattern lists. `no third-party assurance` fires three false positives on reasons using 查證 in its ordinary sense of *verifiable* rather than *third-party assured*. `cites concrete figures present` misses nine reasons that quote figures without using a word like 數據.

The coder is deliberately left unchanged. Tuning it against the same sixty items used to measure it would report an agreement that no longer means anything, and the two load-bearing categories need no tuning. The correct fix for the weak categories is a larger hand-coded set from an annotator who did not write the patterns.
